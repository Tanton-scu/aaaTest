# 环境准备与外部依赖

## 必需

- Docker Desktop 或兼容 Docker Engine/Compose；
- 首次构建时可以访问 Python package index、MySQL 与 Redis 镜像仓库；
- 8000 端口未被占用。

## LLM API

`.env` 中配置：

```text
LLM_API_ENDPOINT=https://provider.example/v1/chat/completions
LLM_API_KEY=不要提交到 Git
LLM_MODEL=model-name
```

三项全部留空时使用 deterministic FakeLLM，不阻塞一键 Demo；只填写一部分会拒绝启动，防止把不完整配置误认为真实模型调用。API Key 不写入代码、Dockerfile 或镜像。

## Literature PDF（可选）

把 PDF 放入 `data/papers/`，然后执行：

```powershell
python -m pip install -e ".[papers]"
python scripts/ingest_papers.py
```

没有 PDF 不影响 Dataset/Prior/PriEvO 主流程。

Compose 方式会把 `data/literature/` bind mount 回宿主机。Linux 主机需保证容器用户对该目录可写；遇到脚本给出的权限诊断时，优先在宿主机执行上述命令，避免生成 root-owned 文件。

## Dataset

项目已自带四个示例。新增 CSV 放入 `resources/datasets/`，列名必须遵循 `$<`、`+$<`、`F$` 规则。无效文件只记录中文 warning，不会让应用整体崩溃。

## Full Mode 验收

当前机器必须先启动 Docker daemon：

```powershell
docker compose config --quiet
docker compose up --build -d
docker compose exec -T app python scripts/full_mode_smoke.py
```

不要把“Compose 能解析”写成“MySQL/Redis 已集成通过”；只有 smoke 成功后才能这样描述。

当前 smoke 断言总预算 42，并验证四个 operator 各生成 P=2、累计 4P=8 后与 retained P=2 统一 `5P → P`、独立 Worker、MySQL/Redis、Agent 主链 Artifact 与 Final Optimization；五类 Agent 的完整正常/故障分支由 Agent Harness 单独覆盖。脚本默认全局截止 600 秒；首个 Job 30 秒无人领取即失败，可由 `.env` 的 `FULL_MODE_SMOKE_TIMEOUT_SECONDS`、`FULL_MODE_SMOKE_WORKER_READY_TIMEOUT_SECONDS` 调整。2026-08-08 的旧包、旧事件数和旧测试数不再作为 1.0.0 发布证据；最新边界见 `docs/RELEASE_AUDIT.md`。
