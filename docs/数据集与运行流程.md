# 数据集与运行流程

## Dataset 格式

- 包含 `$<` 的列：需要最小化的 dependent/performance；
- 以 `+$<` 开头：Loader 读入后取负，与 PriEvO 一致；
- 以 `F$` 开头：fidelity；
- 其他列：configuration parameter，可为数值或 categorical。

Registry 扫描真实文件并计算 SHA-256，不接收前端路径。`dataset_id` 是文件 stem。

## 一次 Run

1. API 通过 Registry 解析 `dataset_id`；
2. 创建 Task/Run，并把 Dataset ID 写入二者；
3. PriEvOEngine 加载同一 CSV；
4. 从 bundled PriEvO FLA knowledge 取得目标的 100-sample recorded metrics；
5. 数值距离检索历史实例，LLM 可用时可替换 semantic refiner；
6. prior optimizer code 初始化 population；
7. 按论文 schedule 演化：前期顺序为 `i1/e1/e2/m1`，后期为 `e1/e2/m1/m2`；
8. 每个 active operator 生成 `population_size` 个 offspring；四个 batches 全部评价后，把 `4 × population_size` 个 offspring 与原 population 合并并一次筛回 `population_size`；
9. EvaluationJob 使用同一 Dataset ID 执行 Offline Dataset evaluation；
10. 每代保存 population、budget、core random state、prior refs、Dataset ID/digest；
11. 最终 Run 保存 best candidate ID 和 FINAL_HEURISTIC artifact。

候选数与预算：

```text
每代 offspring = 4 × population_size
candidate_count = population_size × (1 + 4 × generations)
total_budget = candidate_budget × candidate_count
```

例如 `population_size=10` 时，每个 operator 生成 10 个、一代共生成 40 个；40 个与原来的 10 个组成 50 个，再按该阶段规则筛回 10 个。`generations=4`、`candidate_budget=20` 时，共评价 170 个候选，总预算为 3400。

恢复时只要 Dataset ID 或文件 digest 改变，就拒绝 checkpoint，避免 prior 与 evaluation 指向不同目标。

## Prior 与 Literature

Prior Retrieval 从目标 Dataset 的 landscape metrics 出发，会影响初始 population。Literature RAG 从 PDF 文本出发，只提供研究证据，不参与 numerical instance similarity。
